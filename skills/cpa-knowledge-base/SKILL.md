# 注册会计师专业知识库检索与交叉验证

经 ima 连接器检索订阅的三个专业知识库，为审计工作提供**可溯源的准则依据**；通过「分类路由 + 每库限量 + 三库交叉验证」兼顾全面性与输出稳定性，避免无差别全量检索导致的过度分析与结论漂移。

## 前置条件

- **ima 连接器必须处于已连接状态**。未连接时提示用户在 WorkBuddy 设置页连接 **ima**，不要绕行网页或其他接口。
- 工具由 ima 连接器提供，参数以服务端实际下发的 schema 为准（`search_knowledge` 不接受 `limit` 参数，仅 `knowledge_base_id` + `query` 必填）。
- 鉴权失败（401 / 票据过期）时提示用户重新连接，不要反复重试。

## 查询路由（先分类，再决定查哪些库）

| 问题类型 | 主查库 | 用法 |
|---|---|---|
| 会计准则原文 / 编号 / 修订日期 | 信永中和（全文）+ 会计审计（HTML 全文核对编号） | 可全文取回 |
| 监管提示 / 处罚案例 | 信永中和 | 权威优先 |
| 年报问询函回复 / IPO反馈 / 实务判例 | CPA注会（发现层） | 仅标题+摘要；全文提示去 ima 客户端 |
| 税法 / 国际税收 | CPA注会 + 会计审计 | 两库互补 |
| 内控 / 审计程序 / 案例 | 会计审计（法规类/案例类） | — |

> 路由原则：**按问题类型定主查库，不三库无差别平推**。可多库，但按需，不盲目 fan-out。

## 检索流程（顺序不可跳）

1. **分类路由**：先用上表判断问题类型，确定主查库（可多库，但按需）。
2. **定位知识库**：优先用登记表 ID；表外先用 `search_knowledge_base` 按名称检索拿到 `knowledge_base_id`。**不得凭记忆拼造 ID**。
3. **库内检索**：`search_knowledge`，必传 `knowledge_base_id` 与 `query`。**每库限量取 top 5–8 条，绝不灌满 100 条**。建议叠加过滤：只要 `MEDIA_PARSE_SUCCESS`、排除 `FOLDER`。
   - 长句、多条件复合问题检索精度有限（实测会漂移），**先用单一核心名词**；结果偏离或未命中就**换关键词重试**，最多拆成 2–3 次分主题检索。
4. **取全文纪律**：仅对最相关且 `can_fetch_content` 为 `true` 的 **1–2 条** `fetch_media_content` 读取，`media_id` 必须来自上一步返回，不得跨库复用或拼接。**CPA注会一律不取**（取不到）。其余条目用标题+摘要引用，不强求全文。

## 三库交叉验证规则

对准则依据类问题，相关库分别检索后自行汇总，再按判据给结论：

| 情形 | 处理 |
|---|---|
| 三库/两库一致 | 可提高置信度，仍须标注来源 |
| 仅一库命中 | 标注"未获多源确认"，提示需核对官方发布版本 |
| 库间不一致 | 并列呈现差异，**不得择一采信**，提示以官方发布为准 |
| 需要全文 | 取信永中和/会计审计可读全文的条目；CPA注会作判例线索，全文去 ima 客户端 |

> 设计依据：三库可读深度不对等（两个能读全文、一个只能读标题与摘要），所以交叉验证是"**全文 + 元数据/判例线索**"的互补验证，不是同深度互校。不要向用户暗示三库能力相同。

## 引用规范

- 标注格式：**知识库名称 + 条目标题**（标题含准则编号与发布／修订日期时原样保留）。
- **不得标注未实际命中的条目**，不得编造条款号或条文内容。
- 摘要层获得的信息只能表述为"据知识库条目摘要"，不得表述为"准则第 X 条规定"。

## 输出模板（抑制过度分析）

固定结构，避免自由发挥式长串免责：

```
结论：<一句话结论>
依据：<库名+标题>（多源时并列）
冲突/局限：<如有，说明未获多源确认或库间差异>
行动建议：<核对官方/去ima客户端读全文/补充检索>
```

**停止规则**：信永中和（权威）已给清答案且问题非高争议，不再去另两库"找茬"。

## 时效性

- 知识库内容可能滞后于最新发布。涉及当期新发布准则、准则解释、监管规则的，须提示核对财政部、中注协、交易所官方最新版本，**并以官方发布为准**。
- 摘要中带有"时效性""发布日期""生效日期""文号"时，应一并引用，便于使用者复核是否现行有效。

## 免责

库内内容基于公开信息与 AI 生成，**仅供工作参考，不构成审计意见或专业建议**，不能替代注册会计师的职业判断、审计证据评价与法定责任。"信永中和智能专业知识库"自带同类声明。

## 保密（硬约束）

- **不得将客户名称、财务数据、底稿内容、未公开信息作为检索词提交**至该连接器；提问前先脱敏。
- 不得把知识库检索结果直接当作审计证据；只能作为准则依据线索、分析性程序辅助或底稿准备材料。

## 已知限制（实测记录）

- `search_knowledge` **仅返回标题 + 目录（parent_folder_name）**，不含 `can_fetch_content`、不含 `introduction` 全文——它只是定位器；是否可取全文、能否取全文要看 `get_knowledge_list` 的条目字段，全文需 `fetch_media_content`。
- 订阅类库（如 CPA注会、信永中和的上传文档、会计审计的非 HTML 条目）若内容全部/部分为上传文档或笔记，则 `can_fetch_content` 为 `false`，强行取正文报 `code:220030 该文件获取失败`——属平台侧限制，非参数问题，不要反复重试。
- 网页剪藏（`kind=link`）节点指向 ima 分享页时，只能抓到门面页（介绍＋二维码＋示例提问），**抓不到知识库内容**。读 ima 内容一律走本技能的检索链路。
- `get_knowledge_base_list` 的 `params` 是数组不是对象；`get_knowledge_list` 的 `limit` ≤ 50，`sort_type` 只认枚举值。
