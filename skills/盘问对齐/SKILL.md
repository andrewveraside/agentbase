# 盘问对齐（Grill & Align）

动手前先对齐，比做完了返工便宜得多。本技能把"对齐"变成一套可复用的纪律，移植自 mattpocock 的 `grilling` 方法论，并按 WorkBuddy 环境改写。

## 核心心智模型：设计树

把这次要理清的事情看成一棵**决策树**：顶层是一个总决策（例如"要不要接这票进口业务""台账工具怎么搭"），每个决策会挂出若干**子决策**（例如"走一般贸易还是保税""供应商在哪一个国别""币种与结算方式"）。

- **前置依赖**：一个子决策只有在它的父决策和其他前置决策已定后才"可问"。
- **前沿（frontier）**：当前所有"前置已满足、可以现在就问"的决策集合。

## 执行流程

1. **建树**：先用已知上下文（用户的话、文件、已检索到的信息）把设计树搭出骨架，标出根决策和第一层子决策。
2. **逐轮盘问**：每一轮只问**当前前沿**——把这一轮能问的 decision 全部一起问，每条编号、给推荐答案。
3. **事实归我、决策归你**：
   - **事实**（某国税率、某 HS 编码、某个文件里写了什么、某条法规条款）——由本工具调用工具/子代理去查，**绝不反过来问你**。
   - **决策**（方向、取舍、边界、口径）——只交给你拍板；问完一轮，等你的答复再进下一轮。
4. **推进前沿**：你每答一轮，已定的决策会把前沿向外推开，解锁依赖它们的子决策；同时重新计算前沿，问下一轮。本轮里还依赖"未答问题"的子决策，属于**更晚的轮次**，不要混进本轮。
5. **并行查证不阻塞**：如果某条前沿问题需要先查一个环境事实（读文件、查知识库、搜网），**立刻派工具/子代理去查**，不要等你；把"正在查"当作未决前置，只有依赖它的下游问题等待，前沿其余问题本轮照常问。
6. **收口**：当前沿为空——设计树每个分支都走到、没有偷偷假设的空白——本轮对齐完成。**在你确认"已达共识"之前，不要据此采取任何行动。**

## 一轮的呈现格式

每条问题 phrasing 成"答'是'即采纳推荐答案"，降低你的决策成本：

```
❓ Q1 - <问题标题>：<问题正文，可多段，含选项>

➡️ 推荐：<我的推荐答案>

---

❓ Q2 - <问题标题>：<...>

➡️ 推荐：<我的推荐答案>
```

## 用在外贸场景的示例

你抛来一个模糊想法，例如"我想做一票服务器进口"，本技能会不急着报价/查税率，而是先盘问：

- 贸易方式：一般贸易 / 保税区 / 暂时进出口？（推荐：一般贸易，除非货要转口）
- 货权与流向：最终用户是谁、是否涉 3C 强制认证？（事实：我可先查该 HS 编码是否落入 3C 目录）
- 税务目标：是否要申请减免税、是否走协定税率？（事实：我查目的国是否在相关 FTA 名单）
- 结算与币种：付汇币种、是否锁汇？

把这些都问完、你拍完板，才进入真正的测算/执行。

## 边界与纪律

- **只对齐，不执行。** 本技能产出的是"共识"，不是方案落地。对齐完成后，如要执行，另开任务。
- **不替你做决策。** 推荐答案只是建议，最终取舍是你的；若某推荐你不同意，直接改，前沿照常推进。
- **不凭记忆答事实。** 凡涉税率、税号、法规、文件内容，先查（外贸知识库 / 联网 / 读文件）再写入推理，宁可标注"待查"也不编造。
- **保持通用、可复用。** 本技能不绑定某一票货、某一个客户；每次调用动态拉取具体信息。
