# A 股个股价值分析 HTML 研报 · 执行流程

> 本 skill 只固化**执行套路**。金融方法论（估值框架、预期差、风险分层）一律以 `wb-finance-skill` 的 references 为准，不要在这里重复。

## 触发词
- "分析一下 XXX（股票/代码）""XXX 短中长期价值""XX 该不该买""做成可视化 html""同样的分析一下 XXX"

## 前置：必须先加载 wb-finance-skill
按它的第 8 条硬约束匹配 reference。个股全面分析的标准最小集：
`stock-deep-research` + `valuation-pricing`，按问题追加 `quality-growth`（长期价值/增长质量）、`trade-plan`（买卖点）、`peer-comparison`（同业）、`industry-chain`（产业链），产出 HTML 前必读 `html-report-style`。
**不要凭记忆写分析——reference 加载完成后才开始。**

## 步骤 1：并行取数（agentic_search）
一次委派 3~4 个**一句话意图**，并行发起（同一消息内多个工具调用）：

| # | 维度 | 委派 query 模板 |
|---|---|---|
| 1 | 公司+业绩 | `研究 A 股<公司名>（<代码>）的公司业务结构与近年经营业绩表现` |
| 2 | 财务+估值 | `<公司名>（<代码>）近10年财务数据与当前估值水平、历史估值分位` |
| 3 | 走势+研报+公告 | `<公司名>（<代码>）最新股价走势技术面、机构研报观点与近期公司公告动态` |
| 4 | 同业对比 | `<公司名>与<同业1、同业2、同业3>等同业公司的估值与盈利能力对比` |

**禁止**把字段清单/表格格式/"尽可能全面"写进 query——工具自己会拆维度，拆得越细越慢越发散。字段筛选、排序、制图是主 agent 的活。

## 步骤 2：交叉校验（必做，出过真错）
数据回来后逐项核对，**发现分歧先判源，不要静默选一个**：
- **同类字段误读**：52 周区间曾被某源写成"13.35–18.35"，实为 9.00–18.35——13.35 是行情接口里的 `price_ceiling`（次日涨停价）。**遇到区间/极值，回原始接口逐列对表头。**
- **聚合页转录错误**：某聚合页把券商目标价写成"49.71 元"，与研报原文和一致预期（15.30 元）都不符 → 判为转录错误，不采信，并在报告中注明修正。
- **脏数据行**：股东户数事件表存在 `pre_period == period` 的行 → 只用能三点交叉验证的区间。
- **口径差异**：公司披露的"销售净利率"含少数股东损益，自行测算的"归母净利率"会差 0.2~1pct → 图上标"(测算)"并在图注写明差异。
- **自算派生指标必须能对上一手披露**：单季净利用累计值逐季相减，算完与公司披露的单季数比对（如 26Q2 算出 20.142 亿 vs 披露 20.14 亿 ✓），对得上才用。
- **本机数据源固定**：westock（腾讯自选股）给行情/估值倍数/技术指标/资金流/K 线；NeoData 给估值分位/一致预期/股东事件/综合财务指标；公司定期报告为唯一一手来源。

## 步骤 3：HTML 写入（关键：分两遍，避免被截断）
**单次 Write 长 HTML 会在 30~50KB 处被截断**（本流程实测两次）。
做法：
1. **Write #1**：只写 `<head>`（含 CSS）+ 前半 body，末尾放一个占位注释 `<!--SCRIPT_HERE-->`，再写 footer + `</body></html>`。
2. **Edit #1..N**：每次把 `<!--SCRIPT_HERE-->` 替换成「后续章节 + 新的 `<!--SCRIPT_HERE-->`」，逐步推进；最后一轮替换成完整 `<script>`。
3. 交付前确认文件里**不再包含** `SCRIPT_HERE`。

图表挂载必须 **id 与 mk() 一一对应**，最后用脚本核对两边清单。

## 步骤 4：交付前强制自检（缺一不可）
bash 在本机不可用于文本处理（缺 `dirname`/`wc`/`head`），**全部走 PowerShell**；且 PowerShell 工具的 stdout 常常不回显——**把结果写进文件再用 Read 读**。

```powershell
$p = '<html绝对路径>'
$h = [System.IO.File]::ReadAllText($p)
$s = $h.LastIndexOf('<script>'); $e = $h.LastIndexOf('</script>')
$js = $h.Substring($s + 8, $e - $s - 8)
[System.IO.File]::WriteAllText('<临时.js>', $js, (New-Object System.Text.UTF8Encoding($false)))
& 'C:\Users\23171\.workbuddy\binaries\node\versions\22.22.2-3\node.exe' --check '<临时.js>' 2>&1 | Out-String
```
检查四件事，**把结论写入文件再读**：
1. `NODE_EXIT=0` 且无输出 → 内联 JS 语法通过（ECharts option 括号失配是最高频致命缺陷，一处错则整页图全废）
2. `MARKER_LEFT=False`
3. 图表 id 清单 == mk() 调用清单（用正则分别抽取后比对，手工读截图不可靠）
4. 文件尾部为完整 `</body></html>`

## HTML 版式固定套路
- **浅底深字研报风**（`#f4f5f7` 底 / 白卡 / `#12233d` 字），不用暗色仪表盘。
- **首屏结论先行**：TL;DR 有序列表（5 条，短/中/长期各一条 + 估值一条 + 结论一条）+ 4 个 KPI 卡 + 1 个预警 note。
- **章节骨架**：结论先行 → 公司业务结构 → 财务复盘 → 核心矛盾 → 估值（含情景）→ 三层价值卡 → 预期差 → 时点投资分析 → 风险清单 → 数据来源与口径 → 免责声明。
- **三层价值**用三栏 CSS 卡（短期橙 / 中期蓝 / 长期绿），每栏固定四段：结论 / 支撑 / 压制 / 关键变量。
- **情景推演**用三栏卡（悲观/中性/乐观），三栏**只变一个变量**（通常是估值倍数），并把概率与期望值写出来，再与券商一致目标价对照——差异要归因（"券商不给周期下行情景赋概率"）。
- **图/表可切换**：数字密集的趋势块（如 10 年财务）做 `.tabs` 切换，默认看图。
- **红涨绿跌**，图内逐条 `itemStyle` 显式设色（不要依赖全局色板）。
- 图表分工：趋势/对比/占比用 ECharts；产业链/传导链用 CSS 盒子；查阅型多维对照用表格。
- 每张图下方 `.src` 标注**来源 + 时点 + 口径**；研报类数据必须写"非一手来源，需核实原文"。

## 结尾强制
回复末尾与 HTML 免责声明区都要放**固定文案原样**（不得改写、缩减、省略）：
1. `以上内容基于公开数据和量化分析，仅供参考，不构成投资建议。市场有风险，投资需谨慎。任何投资决策应结合个人风险承受能力、资金状况和投资目标独立判断，必要时咨询持牌专业机构。过往表现不预示未来收益。`
2. 涉及具体买卖/价位/仓位的，另附 trade-plan 的"⚠️ 风险提示与免责声明"模板。
