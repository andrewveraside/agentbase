# 外贸工具开发 SOP（总入口）

当你要动手做一件**外贸进口业务侧**的系统/工具开发时，用本技能串起整套开发纪律。它本身不写代码，而是**按顺序调度 7 个专项技能**，并在每个阶段给出"完成判据"与"出口闸门"。

> **适用对象**：你（AT）在外贸进口业务里既做业务开发也做系统开发。本 SOP 把 mattpocock 的编码纪律，与你已有的外贸资产（`外贸知识库` / `外贸法规与实操专家`）串成一条可复用的流水线：业务正确性优先于工程优雅。

## 工作模式（默认：wb 出交接物）

本 SOP 支持两种收口模式，由你在启动时指定；**未指定时默认「wb 出交接物」**：

- **A. wb 全流程做**：走完 ①→⑦，含写码与自审（用 `tdd`/`code-review`），不依赖外部工具。
- **B. wb 出交接物（默认）**：wb 负责 ①→⑥ 的开发前准备，**产出 CodeBuddy 友好的交接包**（`templates/codebuddy-handoff.md` 定义的结构），你拿去 CodeBuddy（IDE）里续写实现。此模式的前提是：经 `search_plugins` 核查，WorkBuddy 当前**无 CodeBuddy 原生连接器**，无法自动联动，故采用「产物交接」。

> 选 B 时，阶段 ⑦ 的交付物即为 CodeBuddy 交接包（见 ⑦），同时仍可选产出自用的经验归档文档。

## 总览：七阶段链

```
① 盘问对齐  (盘问对齐)        ── 需求/方案对齐
      ↓ 设计树清空、无未决假设
② 领域建模  (domain-modeling)  ── GLOSSARY.md 钉死术语 + 关键 ADR 落档
      ↓ 关键术语钉死
③ 架构设计  (codebase-design)  ── 深模块设计 + 设计两次，定接口/边界
      ↓ 接口/边界确定
④ TDD       (tdd)              ── 先写失败测试 → 红→绿→重构
      ↓ 核心路径测试全绿
⑤ 代码审查  (code-review)      ── 双轴自审（规范+规格）后交付
      ↓ 致命/规范问题清零
⑥ 缺陷诊断  (diagnosing-bugs)  ── 任意阶段触发的可插拔环节
      ↺ 解决后回到触发它的阶段
⑦ 交接归档  (handoff)          ── 收口：压缩成经验文档 + 触发归档确认
```

**顺序约束**：①→②→③→④→⑤→⑦ 严格顺序，不可跳步、不可颠倒。⑥ 是**可插拔**环节——开发途中遇到难 bug，随时调用 `diagnosing-bugs`，解决后回到原阶段。

## 各阶段操作指南

### ① 盘问对齐 — `盘问对齐`
- **调用**：`Skill: 盘问对齐`
- **做什么**：把开发目标画成设计树，逐轮只问"前置已满足"的前沿决策，每条给推荐答案；**事实（税率/HS 编码/法规/文件）由我查，决策由你拍板**。
- **完成判据**：设计树走空、无未决假设；你确认"共同理解已达成"。
- **闸门**：**未对齐前不进 ②**。

### ② 领域建模 — `domain-modeling`
- **调用**：`Skill: domain-modeling`
- **做什么**：把 ① 澄清的概念落成 `GLOSSARY.md`（纯词汇，绝不放实现细节）；仅当"难逆转 + 无上下文会意外 + 真权衡"三条件同时满足时才写 ADR。
- **外贸注意**：进口术语极易混用——进口/报关/清关/保税/一般贸易/协定税率/完税价格/关税 vs 增值税/进境 vs 入境——务必动手前钉死。涉及口径可调用 `外贸知识库` / `外贸法规与实操专家` 核对。
- **产物**：项目根 `GLOSSARY.md`（+ 必要时 `docs/adr/`）。
- **闸门**：关键术语未钉死前不进 ③。

### ③ 架构设计 — `codebase-design`
- **调用**：`Skill: codebase-design`
- **做什么**：用深模块词汇（module / interface / seam / adapter / depth）设计；"设计两次"找最优接口；明确模块边界与依赖方向。
- **产物**：架构决定（可写入 ADR 或设计笔记）。
- **闸门**：接口/边界未定不进 ④。

### ④ TDD — `tdd`
- **调用**：`Skill: tdd`
- **做什么**：先确认 seam（公共边界），写失败测试（红）→ 最小实现（绿）→ 重构。规避三类反模式：实现耦合、同义反复、横向切片。
- **产物**：测试 + 实现，测试全绿。
- **闸门**：核心路径测试未全绿不进 ⑤。

### ⑤ 代码审查 — `code-review`
- **调用**：`Skill: code-review`
- **做什么**：双轴自审——规范轴（编码规范 + 坏味基线）与规格轴（是否实现需求）。
- **产物**：审查结论（通过 / 需修复项清单）。
- **闸门**：致命与规范问题未清不交付。

### ⑥ 缺陷诊断（可插拔）— `diagnosing-bugs`
- **调用**：`Skill: diagnosing-bugs`
- **触发**：任意阶段遇到难复现/难定位的 bug。
- **做什么**：先建"能红"的反馈循环，再提假设；用 HITL 模板做人工介入循环。
- **回到**：解决后回到触发它的阶段，继续原流程。

### ⑦ 交接归档 — `handoff` / CodeBuddy 交接包
- **模式 A（wb 全流程做）**：调用 `Skill: handoff`，把会话压缩成交接/经验文档（结构套 session-experience-archive：结论速览/事实矩阵/踩坑判据/可复用命令/待办/一句话总结），结尾触发是否归档进资料库「历史项目经验」。
- **模式 B（wb 出交接物，默认）**：产出 **CodeBuddy 交接包**，作为本阶段核心交付物：
  - **模板**：`templates/codebuddy-handoff.md`（含 SPEC / GLOSSARY / ADR / ARCHITECTURE / TEST-PLAN / 脚手架 / 启动提示 八节）。
  - **做法**：将 ①盘问对齐结论、②领域词表、③架构、④TDD 策略、⑥诊断结论分别填入对应节；第 1 节"关键约束"必须写明合规口径（税率/HS/完税价格等，引用 `外贸知识库` 核对结果）与技术栈，防止 CodeBuddy 自选。
  - **落盘**：写到项目目录 `codebuddy-handoff/`（或单文件 `CODEBUDDY-HANDOFF.md`），连同已生成的 `GLOSSARY.md` / `docs/adr/` 一并交付。
  - **产物**：一份 CodeBuddy 可直接 ingest 的包 + （可选）自用经验归档文档。
- **闸门**：交接包未生成、关键约束未填，不视为收口完成。

## 使用方式
- **显式调用**：`Skill: 外贸-开发SOP`，或直接说"开搞""开始开发""写个 XX 工具""开发SOP""搭个台账"。
- 本技能是**总入口**：真正干活的是被调度的 7 个专项技能。它的价值是确保每次开发都走同一套纪律、不跳步、不靠记忆。

## 注意事项
- 阶段 ⑥ 可随时插入；①→②→③→④→⑤→⑦ 顺序不可乱。
- **外贸业务正确性优先于工程优雅**：凡涉及税率 / HS 编码 / 合规口径，先用 `外贸知识库` 核对，再写码。
- 本 SOP 不替代领域知识，只保证开发过程有纪律、可沉淀。
